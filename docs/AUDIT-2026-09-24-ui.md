# UI/UX-аудит витрины, кабинета и панели — 24 сентября 2026

Система, к которой приводилось оформление, описана в `docs/design-system.md`.

## Как проверялось

Те же проверки и правки, что у второго магазина проекта (там аудит проводился по живой разметке). Магазин запускался локально на временном каталоге данных. Headless Chrome
снимал 23 страницы (витрина, документы, 404, вход и кабинет, все разделы
панели) на двух вьюпортах: 1440×900 и 390×844 с сенсорным вводом. Затем
скрипт в браузере прошёл по живой разметке каждой страницы и проверил:
- контраст каждого видимого текста с учётом полупрозрачных фонов;
- кнопки и ссылки без доступного имени;
- поля без подписи;
- цели нажатия меньше 24×24 px.

До правок и после них прогонялся полный `npm test` (886 тестов) и
`npm run css:critical:verify`.

## Что сознательно не менялось

Это решения владельца, записанные в CLAUDE.md и закреплённые тестами. Аудит
их не отменяет:
- оформление панели на TailAdmin и его брендовая палитра (кнопки `brand-500` проходят порог);
- подпись «online» в шапке панели;
- `user-scalable=no`: поведение как у приложения;
- «Выйти» внизу кабинета, пароль во всю ширину сетки;
- градиент главной кнопки, розовый `--sale`, цвета мессенджеров.

## Что осталось на следующий заход

- Звёзды рейтинга: пустые звёзды `#d2d2d7` дают 1.5:1, жёлтые `#ff9f0a` — 2:1.
  Рядом всегда стоит число, так что смысл не теряется. Для графики порог 3:1,
  и звёзды можно притемнить, если владелец согласится изменить вид.
- `.section-kicker` на странице 404: акцент на сером фоне 4.39:1. Цвет
  задаёт настройка магазина.
- В `styles.css` три блока `:root`, каждый следующий перебивает предыдущий.
  Их можно свести в один только с полной сверкой вычисленных стилей: так
  делалось при разделении CSS на два файла.
